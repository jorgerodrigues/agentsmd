Debounce the low-battery alarm

The alarm now waits for three low readings in a row. It clears only after the battery recovers above 3.35 V.

Architecture

Each ADC reading goes through one handler. The handler counts low readings and decides when to raise or clear the alarm.

  1. ADC interruptReads the battery through the 1:2 divider every 100 ms.
  2. vbat_on_sample()Converts the reading to millivolts and counts low readings.
  3. AlarmRaised on the third low reading. Cleared at 3.35 V or more.

Code walkthrough

The sample handler counts low readings

A reading below 3.30 V adds one to the count. The third one in a row raises the alarm. A reading at 3.30 V or more resets the count, but only 3.35 V or more clears the alarm.

firmware/power/vbat.c 
if (mv < VBAT_LOW_MV) {
    if (low_count < LOW_READINGS_MAX && ++low_count == LOW_READINGS_MAX) {
        alarm_raise();
    }
    return;  /* hysteresis: only a high reading clears */
}

The divider halves the battery voltage, so the code multiplies by 6600 and not by 3300.

A reading between 3.30 V and 3.35 V resets the count but does not clear an active alarm. That gap is on purpose.

Why three readings?

Motor start pulls the rail down for about 150 ms. Three readings 100 ms apart span at least 200 ms, so a start never raises the alarm.
